## A9 setup/init dialog order (2026-10-17)

Third harness test (`memory: "configured"`, real pi over RPC) passed on the first run with `world.pi.unexpected` empty.
The step queue is strict (`#answer` takes the next step per dialog; `#endTurn` throws on unused steps), so the order
in `configureMemory` is the recorded order. No repair `confirm` fires on a missing config.

- `/memory-setup`: `select` capture model, `select` agent model, `select` "Global memory vault" (attach option),
  `input` "Vault folder (absolute path)"; ends with the setup-done notice.
- `/memory-init`: `input` project name, `input` project vault folder; ends with the init-done notice.

No change to `configureMemory` was needed.

Haiku test failure (measured): the first run's turn ended with `stopReason: "error"`, Anthropic 400 "Third-party apps now
draw from your extra usage, not your plan limits". The child ran with `-ne`, so it lacked `@gotgenes/pi-anthropic-auth`, the
extension the user's pi loads to shape `sk-ant-oat` requests. `get_last_assistant_text` returned `data: {}` because pi
returns `undefined` when the turn has no text.

Fix: `tests/helpers/e2e-anthropic-auth.ts` reads the user's real `~/.pi/agent/settings.json` (read only), finds the package
named `@gotgenes/pi-anthropic-auth` (local path as is, `npm:` under `<agent dir>/npm/node_modules`), and `piArgs` passes
each of its `pi.extensions` as an extra `-e`, keeping `-ne`. It throws a message naming the extension if not found.

After the fix: Haiku test passes (cost line printed). Test 1 now fails because the extension adds the command
`anthropic-auth:status` to the extension-sourced commands.

Decision: test 1 stays strict about our own extension. It filters the `get_commands` entries on
`sourceInfo.path === extensionPath()` (the `-e` path the harness passes) and asserts exactly the four memory commands;
it is renamed "our extension's commands are exactly the four memory commands".

Final result: 3 of 3 pass, 32.24 s.
